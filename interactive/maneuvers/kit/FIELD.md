# Battlefield view kit (`kit/field.mjs`)

Every Maneuvers figure gets a toggle between its **Machine** view and a **Battlefield** view: the same concept as wargame counters on a sand table, driven by the same `model.mjs` state and the same readout. Reference implementation: `flank-attack/` (`scripts/field-scene.mjs`, `scripts/build.mjs`, `scripts/page.html`). Copy it.

All functions are pure and take the iso kit as `K` and a projection `P`, so `build.mjs` calls them in Node and the page inlines `field.mjs` (exports stripped) and calls them per frame. Only `fdPlace` touches the DOM (page only). Ground level on the table is `z = 0.4` (the floor slab's top); pass that as `z` to everything standing on the floor.

## API

**Tokens.** `FIELD_CSS`: append to `ISO_CSS` in the page `<style>`. Muted affiliation colours with light and dark values (`--field-blue`, `--field-blue-top`, `--field-blue-fill`, `--field-red…`), `--field-water`, `--field-wood`, the classes below and the `.fd-views` segmented control. Colour is only for affiliation; the one `lit` accent is the main effort.

**Helpers.** `fdRand(seed)` deterministic random; `fdFrame(x, y, deg)` → `(u, v) => [x, y]` turned frame (u forward); `fdPolar(cx, cy, r, deg)`; `fdSweep(a0, a1, step)` angles ending exactly on `a1`; `fdSpline(pts, n, closed)`; `fdBlob(cx, cy, r, seed, wobble, steps, squash)` irregular outline; `fdInset(ring, d)`; `fdInside(ring, pt)`; `fdOffset(pts, d)`; `fdRibbon(pts, w)`; `fdClipPoly(ring, rect)` / `fdClipLine(pts, rect)` (clip to the table's inner rect so things end on the frame); `fdView(K, P)`; `fdHull(pts)`.

**Solids.** `fdPoly(K, P, faces, style)` any convex solid from 3D faces (shaded, creased, hull outline); `fdCone(K, P, cx, cy, r, z, h)`; `fdHouse(K, P, F, len, wid, eave, ridge, z)`; `fdBox(K, P, F, u0, u1, v0, v1, z0, h, bevel)` → kit paths for `K.solidSvg`.

**Table.** `fdTable(K, P, { plate, inner, frame, frameH, ruler: {x, y, w, d, km, text}, label: {x, y, w, d} })` → `{ back, front }`: plate on feet, floor, frame bars with inlays and screws, scale bar (alternating quarter-km blocks, ticks, one tiny engraved label, e.g. `"KM · NOTIONAL"`) and label plate. Draw `back` first and `front` last. `fdGrid(K, P, inner, step, z)` faint grid, frame to frame.

**Terrain** (strings go in the ground layer; items are depth-sorted):
- `fdHill(K, P, [{ ring, h }…], z)` → `{ svg, top, ring }` stacked contour slabs, each with a faint contour line. Rings from `fdBlob`. Things on the summit stand at `top`.
- `fdWood(K, P, ring, trees, z)` → `{ base, items }` tinted wood floor plus one item per tree. `fdScatter(ring, n, { seed, gap, r, h, avoid, margin })` places trees; use `avoid(x, y)` to keep a track clear. `fdTree(K, P, t, z)` one conifer.
- `fdRoad(K, P, pts, w, z, { tone, smooth, clip })` flat ribbon; `fdRiver(K, P, pts, w, z, seed, clip)` water, banks and fading ripples. Run their ends past the frame and pass `clip: inner`.
- `fdField(K, P, cx, cy, w, d, deg, n, z)` ploughed field (outline + furrows); `fdHedge(K, P, pts, opts)` → item; `fdBush`; `fdSilo(K, P, x, y, z)`.

**Units.** `fdUnit(K, P, U)` → item `{ key, svg }`. `U = { x, y, z, face, side: "f"|"h", fn: "inf"|"armor"|"mech"|"arty"|"recon", ech: "plt"|"coy"|"bn", minis: "inf"|"veh"|"none", lit, len = 40, wid = 28, id }` (defaults sized to read first on a busy board; figures and vehicles scale with `wid`). A rounded stand turned to `face` (degrees, its front lip marks the facing), a round token at its rear whose engraved symbol stays upright to the reader (so a turning unit never shows its symbol upside down), and miniatures along the front. Friendly is a rectangle frame, hostile a diamond; X infantry, oval armour, both mechanized, dot artillery, diagonal recon; echelon `•••`, `I`, `II` above the frame (bars rooted on the frame). `fdSymbol`, `fdFigure`, `fdVehicle` are its parts.

**Control measures** (physical, no text, no arrows): `fdPhaseLine(K, P, pts, z, { skip })` → `{ ground, items }` pegs with an engraved line peg to peg (skip pegs on a track; the line still runs through); `fdPeg` (start point, end point, checkpoint); `fdStakes(K, P, pts, z)` boundary; `fdObjective(K, P, x, y, z, { h, ang })` post and flag; `fdBerm(K, P, cx, cy, r0, r1, a0, a1, z)` prepared position; `fdFan(K, P, cx, cy, r0, r1, a0, a1, z, { side, arcs, alpha })` fire sector; `fdOutline(K, P, ring, z, { side })` battle or support position; `fdTrail(K, P, pts, z, { side, dotted })` route marks. Every line must end on something: start a trail on a peg and end it under a unit.

**Layering.** `fdStatic(items)` writes `<g data-k>` groups in key order (`dyn: true` items get `data-dyn`). `fdPlace(layer, items)` (page) swaps in the per-frame items between the static ones without re-rendering them.

## Recipe: add a Battlefield view to a figure

1. **Map the model.** Write `scripts/field-scene.mjs` with three exports: a layout object, `fieldStatic(K, P)` → `{ table, items }`, and `fieldLive(K, P, S, GEO)` → items for the units and anything else that moves. `fieldLive` reads the *same* state `S` the machine's loop updates; never add a second model. Import from `../../kit/field.mjs` at the top (the build strips `import` lines when inlining).
2. **Keys.** Ground items: `-1e6 + order*100 + n` (grid 0, river 1, wood floors 2, fields 3, roads and marks 5); per-frame ground marks (fans, trails) `-1e6 + 900`. Standing items: `K.depthOf([x, y, 0], P)`. Things on a hill's summit: just above the hill's key (`hillKey + 0.001 + (depth + 100) * 1e-6`).
3. **Layout rules.** The default stand (40 × 28) reaches about 24.4 units from its centre (20 along its facing): keep trees, pegs, stakes and houses that far clear at every pose (in flank-attack the track corridor is ±25.5, a summit unit needs a plateau radius above 24.4 plus any shift). Units must be the first thing the eye finds: keep the board dense (woods, a village, a river and roads, a few fields and hedges) but quiet near the units and the main effort's track; put decorative fields, houses, hedges and copses toward the edges, not between the units. Show each force's fires with a fan (`fdFan`, red for the enemy, blue for friendly, e.g. a support-by-fire sector aimed at the enemy's front that fades with `alpha` when it lifts). Run roads and rivers past the frame with `clip`.
4. **build.mjs.** `const PF = k.fitProjection([...k.boxCorners(plate, -17, 0), tallest point], W, H, { pad: 14, azimuth: 55, elevation: 46 })`. Build `fieldSvg = k.figureSvg({ className: "<root>-field", label, body: [table.back, '<g data-part="field-live">' + fdStatic([...statics, ...fieldLive(k, PF, START, GEO).map(i => ({ ...i, dyn: true }))]) + '</g>', table.front] })` and put it in the stage after the machine SVG. Strip `^import` and `^export` when inlining; inline `kit/field.mjs` then `field-scene.mjs` after the kit. Give the page's `K` at least: `depthOf, iso, cameraOf, solidSvg, lineSvg, dotsSvg, fadeLineSvg, faceTextSvg, extrude, towardViewer, pathOf, onTop, cylinder, slabOf, sideSeam, sideArc, lineOnTop, ring, corners, insetPlan, planOutline, topMatrix, topTicks, haloOf, knurl`. Add `FIELD_CSS` after `ISO_CSS`. Pass `PF` in `DATA`.
5. **Toggle UX (same on every figure).** In the controls row, first: `<div class="fd-views" role="group" aria-label="View"><button type="button" data-view="machine" aria-pressed="true">Machine</button><button type="button" data-view="field" aria-pressed="false">Battlefield</button></div>`. In the live code: `let view` read from `localStorage.getItem("maneuvers.view")` inside try/catch (shared key, so the choice follows the reader across figures; default `"machine"`); `setView(v, save)` sets `root.dataset.view`, `aria-pressed`, the hint corner text, the stage `aria-label`, any per-view control label, saves inside try/catch, and calls `draw()`. Key **V** on the stage toggles. `draw()` renders only the visible view: `if (view === "field") fdPlace(fieldLayer, fieldLive(K, PF, S, GEO)); else <machine draw>`. The tour, slider, buttons and keys stay as they are and drive `S`, so they work in both views. For pointer picking, use `PF` and the field SVG's `getScreenCTM()` when the field view is shown. Expose `setView` and `view()` on the test handle.
6. **CSS.** `.<root>[data-view="field"] .<machine-svg>, … .<legend-machine> {display:none}` and the reverse for the field SVG and legend; give the field SVG `display:block;width:100%;height:auto`; at ≤520 px add `.<stage>{overflow:hidden}.<field-svg>{width:110%;margin:0 -5%}`.
7. **Legend and caption.** Build a second legend with `k.plateHtml({ keys, caption })`, cut out its `<figcaption>` contents, and put both legends in the card's figcaption as `<div class="… fd-keys">` blocks toggled by CSS. Field keys: `lit` main effort, `blue` friendly, `red` enemy. Reuse the machine caption's verified quotes; change only the sentence that maps the object.
8. **Page text.** Add one short "Battlefield view" paragraph to "How to read it": what each unit and marker is, and that unit sizes, distances and the scale are notional. Make no new doctrinal claims; if you must, quote and source them in FACTCHECK.md.
9. **Verify** (one headless Chrome at a time): `lines.mjs` reads only the visible view, so use a drive script: `["eval", "window.__x.stop(); window.__x.setView('field')"]`, `["lines"]`, then a second pose (`until` the defender settles) and `["lines"]` again, and the same in the machine view; all must print `line ends: 0`. Console clean, no sideways scroll at 390 px, `model.test.mjs` passes, 4× close-ups of counters and terrain. Keep the machine thumbnail.
